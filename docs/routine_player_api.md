# 루틴 플레이어 API 비교

담당: 염윤서. 실행 노트북: `notebooks/04_eda_윤서.ipynb`.
재사용 코드: `src/nfa_video_api.py`, `src/routine_comparison.py`.

## 명세에서 확인한 사실

출처: [공공데이터포털 공식 API 명세](https://www.data.go.kr/data/15108846/openapi.do)의
내장 Swagger, 확인일 2026-09-06.
기본 주소: `https://apis.data.go.kr/B551014/SRVC_TODZ_VDO_PKG`.
공통 요청: `serviceKey`, `pageNo`, `numOfRows`, `resultType`.
페이지당 최대 1,000행. 아래는 **사용자가 지정한 7개 필드만** 비교한 표다.
기타 연령·운동명 등의 요청 조건은 이번 비교 클라이언트에서 노출하지 않는다.

| 오퍼레이션 | 제공하는 비교 필드 | 그중 서버 요청 필터 | 명세 기준 역할 후보 |
|---|---|---|---|
| `TODZ_VDO_FTNS_CERT_I` | 체력요인, 도구, 길이 | 체력요인, 도구 | 측정 안내용, 일상 루틴 우선순위 낮음 |
| `TODZ_VDO_TRNG_VIDEO_I` | 장소, 도구, 길이 | 장소, 도구 | 장소 조건 보완 후보 |
| `TODZ_VDO_MSCL_TRNG_I` | 부위, 도구, 길이 | 부위, 도구 | 부위 조건 보완 후보 |
| `TODZ_VDO_STD_FTNS_I` | 길이 | 없음 | 지정 필드만으로 루틴 선별 어려움 |
| `TODZ_VDO_ROUTINE_I` | 체력요인, 준비·본·정리, 목적, 도구, 부위, 길이 | 준비·본·정리, 목적, 도구 | 주 사용 후보, 장소 정보 없음 |
| `TODZ_VDO_VIEW_ALL_LIST_I` | 길이 | 없음 | 전체 목록·중복 대조 후보 |
| `TODZ_VDO_TRNG_GUIDE_I` | 체력요인, 도구, 장소, 길이 | 체력요인, 도구 | 체력요인·장소 보완 후보 |

필드 대응: 체력요인=`ftns_fctr_nm`, 준비·본·정리=`trng_se_nm`, 목적=`trng_aim_nm`,
도구=`tool_nm`, 장소=`trng_plc_nm`, 부위=`trng_part_nm`, 길이=`vdo_len`.
명세는 필드 존재만 알려준다. 실제 결측률이나 값 범위를 증명하지 않는다.
특히 `vdo_len`은 숫자/문자 타입이 혼재하고 단위가 명시되지 않아 숫자 값을 초로 가정하지 않는다.

## 실행

기존 `requirements.txt`의 환경을 준비하고 저장소 루트에서 Jupyter를 연다.
`.env`에 `DATA_GO_KR_KEY` 또는 기존 예시의 `API_KEY`를 설정한다.
두 값이 모두 있으면 `DATA_GO_KR_KEY`를 우선한다. 같은 이름의 환경변수는 `.env`보다 우선한다.
키는 노트북 셀·결과·로그·Git에 넣지 않는다. `DATA_DIR`은 `pathlib.Path`로 해석하며
상대 경로는 저장소 루트 기준이다. 기본값은 `data/raw`다.

1. 명세 비교표를 확인한다. 키 없이도 실행 가능하다.
2. 7개 오퍼레이션을 무필터·동일 예산으로 수집한다. 기본 100행 × 최대 3페이지.
3. 실제 값 분포를 보고 `NUMERIC_UNITS`와 `SCENARIOS`를 설정한다.
4. 필요한 경우 `CHECK_URLS=True`로 HEAD 접근 검사를 실행한다.
5. 관찰 범위와 제한을 고려해 선정표의 주 사용/보완용/제외/추가 확인 필요 및 이유를 작성한다.
6. 기본 Git 제외 경로에 비교표와 평가 결과를 저장한다. 공유할 때 원본 표본은 커밋하지 않는다.

HTTP 429/일부 5xx와 연결 오류만 최대 2회 재시도한다. API 자체 오류는 성공이나 빈 결과로 처리하지 않는다.
실패한 오퍼레이션도 실패 상태와 수집한 페이지 정보를 유지해 비교표에 남긴다.
표본은 시작·중간·끝의 일정 간격 페이지이며 무작위·통계적 대표 표본은 아니다.
`max_pages`가 모든 페이지를 포함하고 건수·페이지 메타정보가 일치할 때만 전수로 표시한다.
조회 중 데이터가 바뀌어도 총건수가 같으면 감지하지 못할 수 있다.

## 해석과 한계

- 금지한 `rptt_tcnt_nm`, `ecrg_cycl_nm`, `trng_hr_nm`은 응답 투영 시 버린다.
  다른 횟수·단계·주차 필드도 이번 비교에는 사용하지 않는다.
- 결측은 필드 없음/null/공백으로 구분한다. 배열·객체 등 예상하지 않은 값은 invalid다.
  길이 문자열의 실제 해석 성공률은 일반 유효 값 비율과 따로 계산한다.
- 원본 행 수와 고유 영상 수는 다르다. 같은 영상의 장면 행이 반복될 수 있다.
  URL 기준 중복률을 제공하며 `row_num`, 제목, 파일명으로 서로 다른 영상을 합치지 않는다.
  쿼리가 다른 URL은 같은 영상일 수도 있지만 확인 없이 합치지 않는다.
- 조건별 조합은 단계마다 고유 영상 1개씩 고르는 최소 검증이다. 여러 동작·세트 최적화는 범위 밖이다.
  한 URL의 길이가 충돌하면 후보에서 제외한다. 표본에서 조합이 없다고 서비스 전체가 불가능한 것은 아니다.
- 장소·부위가 없으면 조건 충족으로 처리하지 않는다. 부위 명칭이 운동의 부담·금기를 뜻하지는 않는다.
  짧은 영상이나 절반 길이는 저강도를 뜻하지 않는다.
- URL HEAD 접근, 영상 Content-Type, 브라우저 재생은 별개다. 실제 재생·코덱·CORS는 별도 확인해야 한다.
- 동일 URL의 다른 행·다른 오퍼레이션 속성을 자동 결합하지 않는다.
  주 후보에 더하는 영상 수와 조건 충족 근거를 보고 필요한 최소 오퍼레이션 조합을 결정한다.

## 검증

저장소 루트에서 `python -m unittest discover -s tests -v`.
실데이터를 흉내 낸 테스트 데이터는 응답 구조와 경계 조건을 확인하기 위한 것이며 실제 API 관측 결과가 아니다.
현재 구현 시점에는 인증키가 없어 실제 호출·최종 선별·브라우저 재생은 미검증이다.
