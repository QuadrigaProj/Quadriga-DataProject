## 📌 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 주제 | 국민체력100 측정 데이터로 **체력나이**를 산출하고, 부족한 체력요인을 보완하는 매일 10~15분 운동 루틴을 처방하는 서비스 |
| 공모전 | 2026년 국민체육진흥공단 공공데이터 활용 경진대회 · 서비스(웹/앱) 개발 부문 |
| 목표 | 측정 → 처방 → 실행 → 재측정 고리를 완성한다. 국민체력100은 측정과 처방을 제공하지만 그 처방을 일상에서 실행할 경로가 없다 |
| 기간 | 2026.09 ~ 2026.10.02 (접수 마감) |
| 활용 데이터 | 공단 오픈API 3종 — 국민체력100 **체력인증센터 측정결과 정보** (공개 296만 건 중 표본 약 13.4만 건으로 분포표 474행 · 처방 빈도표 7,158행) / **동영상 정보** (1,366건 수집) / **체력인증센터 측정건수 정보** (센터 98곳). 여기에 국민체력100 누리집 운동처방 동영상 699편, 카카오 로컬 · 도보 길찾기, Open-Meteo 날씨 · 고도, OpenStreetMap(센터 주소 → 좌표)을 더함 |
| 기획안 | **[docs/기획안.md](./docs/기획안.md)** ← 작업 전 필독 |

## 🎯 핵심 구조

```
⓪ 로그인  카카오 또는 이메일 → 기기가 바뀌어도 이어짐
            ↓
① 진단   집에서 3항목 자가 측정 → 체력나이 78세 (실제 72세)
            ↓
② 목적   다이어트 / 기초체력 / 재활·기능회복 / 수험생 / 유연성 / 벌크업 / 근육량 / 지구력 (8가지)
            ↓
③ 처방   가장 효율적인 약점 하나를 지목 → "근력을 고치면 -4세"
            ↓
④ 실행   매일 10~15분 루틴 (공식 영상 루틴 320개, 10일 순환) · 4주 단위로 세트 조절 (1~4주 2세트, 5주차부터 3세트)
            ↓
⑤ 증명   3개월 뒤 재점검 → 78세 → 75세
```

**매일 숫자를 보여주지 않는다.** 매일 보는 숫자는 곧 무시되지만,
3개월에 한 번 바뀌는 숫자는 기다림이 된다. 이것이 설계의 중심이다.

## ⚙️ 개발 환경 세팅

```bash
# 1. 클론
git clone https://github.com/QuadrigaProj/Quadriga-DataProject.git
cd Quadriga-DataProject

# 2. 가상환경 생성 & 활성화
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 3. 패키지 설치 (서버 실행용)
pip install -r requirements.txt

# 3-1. 분석·노트북까지 하려면
pip install -r requirements-dev.txt

# 4. 노트북 출력 자동 제거 (한 번만)
nbstripout --install
```

패키지를 새로 설치했다면 반드시 반영해주세요.

```bash
pip freeze > requirements.txt
```

### 로그인

| 수단 | 상태 |
|---|---|
| 카카오 | `.env` 에 키를 넣으면 활성화. 없으면 버튼이 비활성으로 표시됩니다 |
| 이메일 + 비밀번호 | 항상 사용 가능 |
| 가입 없이 이 기기에서만 | 로그인 화면 맨 아래 링크. 브라우저에만 저장됩니다 |

로그인하면 측정 기록이 서버에 남아 **다른 기기에서도 이어집니다.**

#### 받는 정보 — 이게 전부입니다

```
로그인 수단 (제공자 식별자 또는 이메일)
닉네임
체력 측정값과 그 결과
```

**휴대폰 번호 · 주소 · 생년월일은 묻지 않습니다.** 소셜 로그인 응답에 그런 값이
섞여 와도 `backend/auth.py` 의 `KEEP_FIELDS` 에서 걸러져 DB 에 닿지 않습니다.
받지 않은 정보는 유출될 수도, 잘못 쓸 수도 없습니다.

계정 삭제(`DELETE /auth/me`)는 측정 기록까지 함께 지웁니다.

#### 비밀번호 처리

평문으로 두지 않습니다. 계정마다 다른 소금(salt)을 만들어 **scrypt**(n=2¹⁴)로 늘려
저장하고, 비교는 상수 시간으로 합니다. 표준 라이브러리만 씁니다.

- 없는 계정과 틀린 비밀번호의 응답을 **같게** 둡니다 (가입 여부를 알아낼 수 없게)
- 세션 쿠키는 `HttpOnly` + `SameSite=Lax` — 자바스크립트가 못 읽고 다른 사이트에서 실려 나가지 않습니다

#### 소셜 로그인 설정

서버를 켜고 **http://localhost:8000/auth/setup** 에 들어가면, 각 콘솔에 등록할
리디렉션 URI 가 **지금 서버 주소 기준으로** 그대로 나옵니다. 복사해서 붙여넣으세요.

> **로그인 화면에는 카카오만 있습니다 (2026-09-21).** 구글 · 네이버는 배포 서버에서 토큰 교환이 막혀
> (구글 `invalid_client` — 콘솔과 Render 의 Client Secret 불일치) 화면에서 뺐습니다. 서버 코드는 남아 있어서,
> 콘솔 · 환경 변수를 맞춘 뒤 `frontend/index.html` 의 `#socialBox` 에 버튼을 되돌리면 다시 켜집니다.

| 제공자 | 콘솔 | 리디렉션 URI |
|---|---|---|
| 구글 | console.cloud.google.com/apis/credentials | `http://localhost:8000/auth/google/callback` |
| 네이버 | developers.naver.com/apps | `http://localhost:8000/auth/naver/callback` |
| 카카오 | developers.kakao.com/console/app | `http://localhost:8000/auth/kakao/callback` |

> **이 주소는 브라우저로 직접 여는 페이지가 아닙니다.** 로그인이 끝난 뒤 제공자가
> 우리 서버를 부를 때 쓰는 통로입니다. 직접 열면 "여긴 통로다" 라는 안내만 나오는데,
> 그게 정상 동작이자 서버가 살아있다는 확인입니다.

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

키를 넣은 뒤에는 **서버를 다시 시작**해야 반영됩니다.

> 권한(scope)은 **이메일 · 닉네임만** 신청하세요. 휴대폰 번호나 생일 항목은
> 신청하지 않습니다. 받아도 서버에서 버리지만, 애초에 요청하지 않는 게 맞습니다.

**카카오는 닉네임만 받습니다.** 이메일(`account_email`)은 콘솔에서 동의항목을 켜도
일반 앱에서는 별도 검수를 받아야 요청할 수 있고, 안 받은 상태로 요청하면
`KOE205` 로 로그인 자체가 막힙니다. 계정 키는 카카오 회원번호라 이메일 없이도
로그인·기기 간 이어보기가 모두 동작합니다.

검수를 통과하면 코드 수정 없이 환경변수만 바꾸면 됩니다.

```
KAKAO_SCOPE=profile_nickname account_email
```

**카카오는 `KAKAO_CLIENT_SECRET` 이 없어도 동작합니다.** 카카오 콘솔에서 Client Secret 은
선택 기능이라 켜지 않으면 값 자체가 없습니다. 켜는 편이 안전하지만(REST API 키가
새어도 남이 우리 앱 행세를 못 합니다), 없으면 요청에서 빼고 진행합니다.
구글·네이버는 필수라 없으면 버튼이 켜지지 않습니다.
>
> 키는 `.env` 에만 넣고 커밋하지 마세요. `.env` 는 `.gitignore` 에 있습니다.

### AI 루틴 추천 (선택)

`목록 → 루틴 추천` 의 **무료 추천**은 운동 목적 · 약점 · 스타일 테스트 · 고른 종목으로 점수를 매겨
공식 영상 루틴 320개 중에서 고릅니다. **AI 추천**(로그인)은 Claude 가 그 사람의 기록을 모두 읽고
(체력나이 · 항목별 결과 · 최근 운동 기록 · 시작일의 계절과 날씨 · 건강 상태 · 운동 예산 · 일정)
**아침 · 낮 · 저녁 · 밤 루틴을 새로 짓습니다** (`backend/ai_recommend.py`). 재료는 국민체력100 공식 동작과
고른 종목뿐이고, 응답의 코드 · id 를 재료 목록에 대조해 없는 줄은 버립니다 — 운동 이름을 지어낼 수 없습니다.
루틴 짓기 · 계절 · 시간대 계획은 Opus, 약봉지 · 시간표 사진 읽기는 Sonnet 입니다.

```
# .env
ANTHROPIC_API_KEY=sk-ant-...
```

키 발급은 [console.anthropic.com](https://console.anthropic.com/settings/keys). 넣고 서버를 다시 시작하면
추천 화면의 AI 추천이 켜지고, 받은 루틴에는 "AI 가 지었어요" 가 붙습니다.

**키가 없어도 추천은 그대로 동작합니다.** 키가 없으면 AI 추천만 잠기고, 호출이 실패하거나 응답이 재료와 맞지 않으면
그 응답을 버리고 값도 받지 않습니다 — 화면이 비는 경우는 없습니다.

### 추천 두 가지 방식과 이용권

| | 무료 추천 | AI 추천 |

| 고르는 방법 | 운동 목적 · 약점 · 스타일 테스트 · 고른 종목으로 점수 | Claude 가 기록 전체를 읽고 시간대별 루틴을 새로 지음 (공식 동작 · 고른 종목 안에서) |
| 값 | 없음 · 횟수 제한 없음 | **1회 500원** (미리 충전) · 시연 기간에는 값 표시는 같고 하루 3회까지 무료 |
| 걸리는 시간 | 바로 | 백그라운드 작업 — 화면에 '보통 N초' (최근 실제 시간의 가운데값) |
| 키 없을 때 | 그대로 동작 | 잠김 |

이용권은 프로필의 **AI 추천 이용권** 카드에서 미리 충전해 둡니다. 잔액·남은 횟수·결제 내역(환불 버튼 포함)이 거기 있습니다.

> ⚠️ **지금 결제는 카카오페이 테스트 가맹점(`TC0ONETIME`)입니다.** 결제창은 진짜여도 돈이 빠지지 않고, 카드 정보는 앱이 받지 않습니다.
> 실결제를 열려면 사업자 등록과 가맹점 계약이 필요합니다. 잔액은 서버 원장(`credit_ledger`)에만 있어 브라우저에서 고칠 수 없습니다.

### 연령군

| 연령군 | 나이 | 연령구간 | 근력/순발력 항목 | 숫자 읽는 법 |
|---|---|---|---|---|
| 성장기 | 11~18 | **1세 단위 8구간** | 제자리멀리뛰기 (cm) | 실제 나이보다 **높을수록** 좋음 (발달 수준) |
| 성인 | 19~64 | 5세 단위 9구간 | 교차윗몸일으키기 (회) | 실제 나이보다 **낮을수록** 좋음 |
| 어르신 | 65+ | 5세 단위 4구간 | 의자앉았다일어서기 (회) | 실제 나이보다 **낮을수록** 좋음 |

> 성장기를 5세 단위로 묶으면 구간이 `10~14`·`15~19` 둘뿐이라 보간이 양 끝값에
> 붙어 누구나 같은 값이 나옵니다. 원본 `age_degree` 는 1세 단위이고 나이×성별당
> 표본이 2,000건을 넘으므로 잘게 나눠도 안정적입니다.
>
> 성장기는 나이가 들수록 기록이 좋아져 방향이 반대입니다. 그래서 응답에
> `해석` 문구와 `또래비교`(백분위)를 함께 주고, 화면도 "발달 수준" 으로 읽습니다.

#### 또래 비교는 더 좁은 창으로 (선택)

환산나이 곡선은 위 구간을 그대로 쓰지만, **"또래 가운데 몇 등인가"** 는 구간을 더 좁혀 견줄 수 있습니다 —
21세를 19~24세가 아니라 **20~22세**와. `backend/build_distribution.py` 가 나이마다 그 나이를 가운데 둔 창
(±1세, 표본이 300명에 못 미치면 한 살씩 넓힘, 연령군 경계는 넘지 않음)의 백분위 표
`fitness_peer_windows.csv` 를 같이 만듭니다.

```bash
python backend/build_distribution.py                                   # data/processed/ 에 두 파일이 생깁니다
cp data/processed/fitness_peer_windows.csv data/sample/                # 배포 서버에는 data/sample/ 만 올라갑니다
```

이 파일이 있으면 서버가 또래 비교에만 좁은 창을 쓰고(`또래비교.*.비교구간` 이 `"20~22"` 로 바뀝니다),
없으면 지금처럼 5세 구간으로 견줍니다. 곡선까지 좁히지 않는 까닭: 한 살 단위 중앙값은 들쭉날쭉해서
환산나이가 튑니다. 원자료(`data/raw/measurements.parquet`)가 있어야 만들 수 있습니다.

### 운동 기록과 체력나이

운동을 기록하면 체력나이가 바로 다시 계산됩니다 (`POST /fitness-age/activity`).

**다만 운동 기록만으로 체력나이를 "측정" 할 수는 없습니다.** 국민체력100 분포는
측정 항목(앉아윗몸앞으로굽히기 · 교차윗몸일으키기 …)의 기록을 나이로 바꾸는
표이지, "스쿼트를 몇 세트 했는가" 를 나이로 바꾸는 표가 아닙니다. 그래서:

- 기준은 **마지막 측정값**입니다. 항목별 환산나이는 측정한 값 그대로 둡니다.
- 최근 **28일** 안에 그 체력요인을 운동한 **날 수**만큼 체력나이를 당기되
  (하루당 0.2세), **그 측정의 편차(신뢰구간)를 넘지 않습니다.**
- 한 요인만 해서는 전체를 끌고 가지 못합니다 — 체력나이가 항목별 평균이라
  당기는 폭도 항목 수로 나눠 실립니다.
- **재측정하면 이 추정치는 버리고 진짜 값으로 덮습니다.**
- 재지 않은 요인(예: 심폐지구력을 측정한 적 없는 사용자)은 운동해도 반영하지
  않습니다. 없는 값을 만들어내지 않는 저장소 원칙 그대로입니다.

화면에는 `운동 12일 반영 −0.8세 · 마지막 측정 38세` 처럼 **측정값과 반영 폭을
같이** 보여 줍니다. 반올림하면 같은 숫자로 보일 수 있어서, 얼마나 움직였는지를
숫자로 적습니다.

이용권을 공짜로 채울 수 있어서 값으로 막는 건 막는 게 아닙니다. 그래서 값 대신 **하루 무료 횟수**(루틴 3 · 구간 계획 3 ·
사진 2, 한 곳(IP)에서 합계 60 — 같은 와이파이의 여러 사람이 막히지 않게)로 제한합니다. 값표는 화면에 정식 결제 때와 같게 보이고(`1회 500원 · 결제 전이라 지금은 무료 · 오늘 N회 남음`), 횟수 제한만 실결제가 열리기 전까지의 임시 장치입니다. `ADMIN_USERS`(`kakao:회원번호` 처럼 `/auth/me` 의 `계정` 값, 소셜 계정은 이메일도 됨 — 비밀번호 계정은 이메일을 확인한 적이 없어 `password:이메일` 로만)에 적힌
계정은 값도 횟수도 없습니다 — 팀이 써 보는 용도. 호출마다 토큰 수가 `ai_usage` 표에 남고 `/ai/usage`(관리자)에서 봅니다.

**한 달 구독 9,900원** (`SUB_PRICE`, 30일 · 자동 갱신 없음 — 사업자 없이는 정기결제 계약이 안 돼 매달 직접 결제):
AI 루틴 하루 5회(조정 포함) · 자세히 보기 포함 · 약봉지 사진 하루 5회 · 커뮤니티 쓰기 한도 완화(글 하루 5→30개 · 사진 3→6장 ·
본문 1,000→3,000자). 구독은 이용권을 거치지 않고 상품으로 결제합니다 — 선결제 보너스로 구독을 싸게 사는 길이 생기지 않게.
하루 5회를 매일 다 쓰는 사람은 원가(3만 원)가 값을 넘으니 `/ai/usage` 로 사용량을 봅니다.

**AI 루틴은 백그라운드 작업입니다** (2026-09-23, `ai_jobs` 표): '받겠다' 고 하면 서버가 작업을 걸고 스레드가 끝까지 짓습니다. 요청은 `JOB_WAIT_SEC`(20초)만 기다려 보고 — 그 안에 끝나면 예전처럼 결과를 바로 — 아니면 작업 번호를 주고, 화면은 `GET /recommend/ai-job/{id}` 를 3초마다 물어 끝나면 그대로 적용합니다. 다른 화면에 가 있으면 알림만 띄우고, 새로고침했으면 `/recommend/ai-status` 의 `작업` 으로 이어받습니다. 값은 실제로 지어졌을 때 스레드가 받으니 요청이 끊겨도 '값은 냈는데 루틴은 못 받는' 일이 없습니다. 짓는 데 두는 제한 시간은 SDK 기본(600초)뿐이고, 화면에는 최근에 실제로 걸린 시간의 가운데값을 '보통 이만큼' 으로 보여 줍니다(`billing.job_typical_sec`).

그때그때 500원씩 내도 되고, 미리 선결제하면 이용권을 더 얹어 줍니다 — 보너스는 25% 까지(=값의 20% 할인). 한 번
쓸 때마다 원가가 실제로 나가서 그보다 깊으면 팔수록 손해입니다.

| 실제로 내는 돈 | 앱에서 쓰는 금액 | 보너스 |
|---|---|---|
| 500원 (1회만) | 500원 | — |
| 1,000원 | 1,100원 | +10% |
| 3,000원 | 3,450원 | +15% |
| 5,000원 | 6,000원 | +20% |
| 10,000원 | 12,500원 | +25% |

**이 표는 서버(`backend/main.py` 의 `PAY_PACKS`)가 기준입니다.** 화면은 서버가
내려준 값을 그리기만 하고, 청구 금액도 서버가 다시 계산합니다. 화면이 보낸
금액을 그대로 청구하면 조작할 수 있기 때문입니다. 승인된 금액이 청구액과
다르면 이용권을 올리지 않습니다.

가격을 바꾸려면 `PAY_PACKS` 한 곳만 고치면 됩니다(화면 쪽 사본은 서버를
못 부를 때만 쓰이며, 테스트가 두 값이 같은지 봅니다).

충전 화면에서 금액과 결제 수단을 고릅니다.

| 수단 | 지금 상태 |
|---|---|
| 카카오페이 | **실제 결제.** `KAKAOPAY_SECRET_KEY` 가 있으면 켜집니다 |
| 신용·체크카드 | 화면만 있고 **결제되지 않습니다** (PG 계약 전) |
| 계좌이체 | 화면만 있고 **결제되지 않습니다** (PG 계약 전) |

카드·계좌는 누르면 "아직 카카오페이만 결제할 수 있어요" 가 뜹니다.
예전에는 모의로 이용권을 올려 줬는데, 잔액이 서버로 옮겨간 뒤로는 그럴 수
없습니다 — 화면에서 올릴 수 있으면 그게 곧 무료 충전 통로입니다.

**카드번호·CVC·유효기간·계좌번호를 이 앱에서 받지 않습니다.** 실제 서비스에서
그건 PG사 결제창이 받아야 하고(PCI-DSS), 우리가 받으면 그 자체가 사고입니다.
그래서 카드사·은행 선택과 버튼은 다 만들되, 실제 정보 입력은 각 결제창으로
넘깁니다. 카카오페이도 결제 정보는 카카오 결제창이 받습니다.

#### 카카오페이 켜기

1. https://developers.kakao.com 에서 앱을 만들고 카카오페이를 신청합니다
2. `.env` 에 넣습니다 (인증키는 총괄에게 요청하세요. **채팅방에 붙여넣지 마세요.**)

```
KAKAOPAY_SECRET_KEY=DEV...
KAKAOPAY_CID=TC0ONETIME
```

3. 서버를 다시 띄웁니다

`KAKAOPAY_CID` 기본값 `TC0ONETIME` 은 카카오가 주는 **테스트 가맹점 코드**라
결제창은 진짜여도 실제로 돈이 빠지지 않습니다. 화면에도 그렇게 적힙니다.
실결제는 가맹점 계약 후 발급받은 코드로 바꿔야 합니다.

#### 흐름

```
화면  → POST /pay/kakao/ready      금액·주문번호만 보낸다
      ← 결제창 주소
카카오 결제창에서 사용자가 결제
      → GET  /pay/kakao/approve    여기서 승인해야 돈이 빠진다
      ← /?pay=ok&order=...
화면  → GET  /pay/result/{order}   승인된 금액을 서버에 다시 묻는다
      ← {"paid": true, "amount": 3000}
```

- **충전 금액은 서버가 확인해 준 값만 씁니다.** 화면이 보낸 숫자를 믿지 않습니다.
- 한 주문은 한 번만 반영됩니다 — 새로고침해도 두 번 충전되지 않습니다.
- 결제만 끝나고 프로필을 아직 안 고른 손님은, 프로필을 고를 때 반영합니다.

#### 잔액은 서버가 들고 있습니다

실제로 돈을 받으려면 이 둘은 브라우저에 둘 수 없습니다.

| | 예전 | 지금 |
|---|---|---|
| 잔액 | 브라우저 스냅샷(`state.credit`) | **`credit_ledger` 원장**. 잔액은 그 합 |
| 주문 | 서버 메모리 | **`pay_orders` 테이블** |

- 브라우저에서 숫자를 바꿔 저장해도 **서버 잔액은 그대로**입니다. 스냅샷에
  잔액을 담지 않습니다.
- **AI 추천 차감도 서버에서** 합니다(`/recommend/routines`). 화면에서 빼면
  브라우저에서 숫자만 바꿔 공짜로 무제한 쓸 수 있습니다.
- 실제로 다듬어졌을 때만 받습니다. 폴백이면 한 푼도 안 씁니다.
- 잔액이 모자라면 AI 를 **부르지도 않습니다** — 부르고 나서 못 받으면 우리만
  돈을 씁니다.
- 한 주문은 한 번만 충전됩니다. `order_id` 에 UNIQUE 를 걸어 **DB 가** 막습니다.
- 준비와 승인 사이에 서버가 재시작돼도 주문이 살아 있습니다.

#### 환불

`POST /pay/refund/{주문번호}` — 산 사람이 스스로 부릅니다. 전자상거래법상
청약철회를 받아야 하므로 이 길이 필요합니다.

**한 번이라도 쓴 선결제권은 환불되지 않습니다.** 쓴 만큼은 이미 제공된
서비스라 돌려받을 게 없고, 일부만 돌려주려면 얼마를 돌려줄지 규정이 있어야
합니다. 지금은 **안 쓴 것만 통째로** 취소합니다(409 로 막습니다).

**카카오에서 실제로 취소된 뒤에만** 이용권을 되돌립니다. 순서가 바뀌면 돈은
그대로인데 이용권만 사라집니다.

#### 실제 결제로 켜기 (총괄이 할 일)

코드는 준비돼 있습니다. 아래는 사람이 해야 합니다.

1. **사업자 등록** 후 카카오페이 **가맹점 계약** → 실제 CID 와 SECRET KEY 발급
2. `.env` 에 넣고 서버 재시작

```
KAKAOPAY_SECRET_KEY=<발급받은 키>
KAKAOPAY_CID=<발급받은 가맹점 코드>
PUBLIC_BASE_URL=https://<배포 주소>
```

3. **작은 금액으로 한 번 실제 결제해 보세요.** 카카오 서버를 실제로 부른 적은
   없습니다(키가 없어서). 요청 모양은 문서대로 맞췄고 테스트로 확인했지만,
   첫 실결제는 눈으로 봐야 합니다. 환불도 한 번 눌러 보세요.

`KAKAOPAY_CID` 를 실제 코드로 바꾸면 화면 문구가 "실제로 결제됩니다" 로
바뀝니다. `PUBLIC_BASE_URL` 은 배포 주소와 정확히 같아야 합니다 — 카카오가
사용자를 그 주소로 돌려보냅니다.

#### 아직 남은 것

- 부분 환불은 없습니다(전액만). 쓴 만큼을 얼마로 칠지 규정을 정하고 붙이세요.
- 결제 화면에 **사업자 정보와 환불 규정**을 표시해야 합니다(전자상거래법).
  계약 후 회사 정보가 정해지면 넣으세요.
- 정기결제(자동 갱신 구독)는 다루지 않습니다 — 지금 구독은 자동 갱신 없는 30일 이용권입니다.

## ☁️ 배포 (Render)

`render.yaml` 이 있어 Blueprint 로 한 번에 올라갑니다.

1. [render.com](https://render.com) 에 GitHub 계정으로 로그인
2. **New → Blueprint** → 이 저장소 선택 → **Apply**
3. 웹 서비스가 생성됩니다. DB 는 [Neon](https://neon.tech) 무료 Postgres 를 만들어(지역은 웹 서비스와 같은 곳)
   연결 문자열을 **Environment** 의 `DATABASE_URL` 에 넣습니다 (`?sslmode=require` 포함 — 코드 변경 없음).
   표는 서버가 처음 뜰 때 스스로 만듭니다
4. 배포가 끝나면 **Environment** 에서 `PUBLIC_BASE_URL` 을 실제 주소로 채웁니다
   (예: `https://quadriga-fitness-age.onrender.com`)
5. 소셜 로그인을 쓰려면 각 `CLIENT_ID`/`CLIENT_SECRET` 도 여기에 넣습니다

> **키는 Render 대시보드에만 넣으세요.** 저장소에 커밋하지 않습니다.

### 저장소는 환경에 따라 갈립니다

| 환경 | DB | 데이터 |
|---|---|---|
| 로컬 | SQLite (`data/app.db`) | 그 컴퓨터에만 |
| 배포 | Postgres (`DATABASE_URL`, Neon 무료) | 서버가 다시 떠도 남음, 기기 간 공유. 만료 없음 — 5분 쉬면 DB 가 잠들어 첫 쿼리에 1초쯤 |

코드는 하나입니다. `DATABASE_URL` 이 있으면 Postgres, 없으면 SQLite 로 붙습니다.
테스트도 양쪽에서 모두 통과하는지 확인합니다.

```bash
pytest -q                                    # SQLite
DATABASE_URL=postgresql://... pytest -q      # Postgres
```

### 배포 후 소셜 로그인

`PUBLIC_BASE_URL` 을 넣으면 `/auth/setup` 의 리디렉션 URI 가 **배포 주소로 바뀝니다.**
각 콘솔에 로컬용과 배포용 **둘 다** 등록해두면 개발과 시연을 함께 할 수 있습니다.

```
http://localhost:8000/auth/google/callback      ← 개발
https://<배포주소>/auth/google/callback          ← 시연
```

## 🧩 역할 분담

**역할은 "누가 이 부분을 끌고 가는가" 이지, "누구 파일인가" 가 아닙니다.**
어떤 파일이든 누구나 고쳐서 PR 올릴 수 있습니다. 남의 코드를 고쳤다면
PR 본문에 왜 고쳤는지 한 줄만 적어주세요.

| 역할 | 주도 | 주로 만지는 곳 |
|---|---|---|
| **A. 체력나이 산출** | 유민진 | `backend/fitness_age.py` · `backend/build_distribution.py` |
| **B. 루틴 · 동영상** | 염윤서 | `backend/daily.py` (영상 필터) · `frontend/` 화면 4 |
| **C. 화면 · UI** | 정다은 | `frontend/` 전체 |
| **D. 처방 로직** | 장예현 | `backend/prescription.py` · `backend/main.py` |

### 의존 관계

```
데이터 수집 (296만 건 페이징)  ← A·D 공통 선행. 한 번만 하고 공유
        ├─→ A 체력나이 ──┬─→ D 약점 지목 계산
        │                └─→ C 프로필·목표 화면에 실제 값 연결
        └─→ D pres_note 파싱 (A와 무관하게 병렬 가능)

B 루틴·동영상 — 거의 독립
```

화면은 이미 `/fitness-age` `/routine` `/daily` 에 붙어 있습니다.
이제 A·D 가 계산을 고치면 **화면은 손대지 않아도 값이 따라 바뀝니다.**
