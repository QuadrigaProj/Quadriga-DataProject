# 체력나이 기반 일상 운동 루틴 및 생활활동 처방 서비스 (시제품)

2026년 국민체육진흥공단 공공데이터 활용 경진대회 · 서비스(웹/앱) 개발 부문 제출용 웹 프로토타입입니다.
[docs/기획안.md](../docs/기획안.md)의 설계를 구현했습니다.

> **범위 안내**: 이 폴더 하나가 담당 배분표의 A(체력나이 산출)·B(루틴 플레이어)·
> C(화면·UI)·D(처방 로직)를 전부 아우르는 **통합 프로토타입**입니다. 각자 맡은
> 영역의 로직/화면을 검토하고, 필요하면 자기 담당 부분만 갈아끼우거나 `src/`의
> Python 분석 결과를 여기 연결해 주세요. 한 사람이 전체를 다 짰다고 다른 담당의
> 몫이 없어진 게 아니라, 그 자리를 채우는 하나의 출발점입니다.

## 빠른 실행

```bash
cd website
npm install
npm start
# http://localhost:3000 접속
```

Node 18 이상이면 별도 설정 없이 바로 실행됩니다. 서비스키가 없으면 자동으로
**샘플(목업) 데이터 모드**로 동작해, 키 없이도 전체 플로우를 시연할 수 있습니다.

## 실제 공공데이터 API로 전환하는 법

저장소 루트 README에 이미 활용신청이 승인된 엔드포인트가 정리돼 있습니다
(측정결과 정보 · 동영상 정보, 유효기간 2026-09-06~2028-09-06). 서비스키는 총괄에게 요청하세요.

1. 저장소 관례대로 `.env`(저장소 루트 또는 `website/.env`)에 키를 넣습니다.
   ```
   DATA_GO_KR_KEY=발급받은_인증키
   ```
   `.env`의 `DATA_GO_KR_KEY`가 있으면 `config.json`의 값보다 항상 우선합니다.
2. 동영상 API는 오퍼레이션이 7종입니다(담당 B 조사 중). `config.example.json`을
   `config.json`으로 복사해 `VIDEO_API_OPERATION`에 실제로 쓸 오퍼레이션명을 채우세요.
3. 센터 위치정보 API는 아직 팀 README에 승인 엔드포인트가 없어 `CENTER_API_BASE`/
   `CENTER_API_OPERATION`은 **추정값**입니다. 확인되면 교체하세요.
4. **실제 Swagger 명세를 열어서** `server.js`의 `fetchVideosLive` / `fetchCentersLive`
   안 필드 매핑을 실제 응답 구조에 맞춰 수정하세요. 실제 API 호출이 실패하면
   자동으로 샘플 데이터로 폴백하므로, 시연 중 키가 막혀도 서비스가 멈추지 않습니다.
5. `npm start`로 재시작 — 콘솔에 `실제 공공데이터 API 호출 모드`가 뜨면 전환 완료

## 체력나이 산출 - 실측 데이터로 교체됨

`server.js`의 체력나이 로직은 이제 합성 추정치가 아니라 **담당 A가 실제
`측정결과 정보` API(296만여 건)를 수집·집계해 만든 `data/fitness_distribution.json`**
을 사용합니다. 같이 받은 `fitness_age.py`("참조 구현")를 JS로 그대로 포팅했습니다.

- `collect_measurements.py` → API 전량 수집, `build_dist.py` → 성별·연령군·연령구간·
  항목별 p5~p95 분포 집계(항목별 상하위 0.5% 윈저화 포함) → `fitness_distribution.csv`
- `server.js`의 `convertAge()`가 `fitness_age.py`의 `convert_age()`를 그대로 옮겨,
  실측 p50 곡선에 선형보간(numpy.interp와 동일한 클램프 방식)으로 역산합니다.
- 연령 구간은 원본 그대로 **성인 5세 단위 9구간(19~24 … 60~64) + 어르신 5세 단위
  (65~69 … 80세 이상 열린구간)** 입니다.
- 자가 측정 보정(윈저화)도 이제 실측 p5~p95 범위(`computeWinsorBounds()`)를 씁니다.

### 참조 구현과 의도적으로 다르게 만든 두 지점

1. **BMI 축.** 참조 구현은 다른 3항목과 똑같이 "`|BMI-22|` 편차 곡선을 연령대와
   대조"하는 방식을 쓰지만, 실측 데이터로 그대로 옮겨 검증해보니 여성 편차가 가장
   작아지는 구간이 35~39세(0.1)에 몰려 있어 **BMI가 22에 가까운 건강한 22세 여성이
   "BMI 환산나이 37세"로 나오는 문제**가 재현됐습니다(처음 합성 데이터로 만들었을 때
   발견했던 것과 같은 종류의 문제가 실측 데이터에도 있었습니다). 그래서 BMI만
   `bmiEquivalentAge()`에서 **"내 나이대의 실제 평균 편차"와 내 편차를 비교**하는
   방식으로 계산합니다 - 편차가 또래 평균과 같으면 환산나이 = 실제나이(중립).
2. **약점 우선순위의 기준점.** 기획안 5-2절 원문은 "또래 평균(실제나이)까지 올리면"
   이라고 적혀 있지만, 참조 구현 `weakest_link()`는 **"세 항목 중 이미 가진 가장
   좋은 값"**을 기준점으로 씁니다. 실제 코드 쪽을 그대로 따랐습니다 - 인구 곡선의
   잡음에 덜 흔들리고, "당신은 이미 이만큼 할 수 있다"는 자기 자신 안의 근거라
   더 명확합니다. `/api/target`(목표 역산, 7절)은 기획안 원문 그대로 실제나이를
   기준점으로 씁니다 - 서로 다른 기능이라 기준을 다르게 유지했습니다.

두 지점 모두 코드 주석에 발견 경위와 이유를 그대로 남겨 뒀습니다(`server.js` 검색:
`BMI_AGE_SENSITIVITY`, `weakest_link`).

**검증**: `scripts/fitness_age.py`를 직접 실행해 여러 성별·연령군·측정값 조합에서
Python 결과와 `server.js`의 JS 포팅 결과(유연성·근력 축)를 대조했고, 모두 일치합니다
(가끔 소수점 첫째 자리가 ±0.1 나는 경우가 있는데, 로직 차이가 아니라 정확히 .5에
걸리는 값에서 파이썬과 JS의 반올림 방식이 다르기 때문입니다 - `npInterp` 주석 참고).

### 실측 데이터에서 발견한 것 (담당 A 참고)

- **`연령군=유아기` 라벨의 일부 행은 나이 값이 45~84로 찍혀 있습니다.** 원자료
  `age_gbn` 라벨링 이상으로 보입니다. 이 서비스는 성인/어르신 구간만 쓰므로 영향은
  없지만, 청소년/유소년 확장(한계 4번) 전에 확인이 필요합니다.
- **여성 유연성(앉아윗몸앞으로굽히기) p50 곡선이 30~60대 구간에서 거의 평평하고
  일부 구간은 나이가 들수록 오히려 소폭 올라갑니다**(예: 45~49세 15.0 → 55~59세
  16.3). `convertAge()`는 참조 구현과 동일하게 "단조가 아니면 값 기준으로
  재정렬"하는 안전장치로 처리하지만, 이 구간에서는 결과가 다소 거칠 수 있습니다.

## pres_note 처방 데이터 (담당 D 영역, 부분 연동)

`exercise_freq.csv`는 실제 `pres_note` 296만여 건을 파싱해 연령군·성별·운동단계
(준비/본/정리)별 운동명 빈도로 집계한 실측 데이터입니다. 현재 `/api/prescriptions`
엔드포인트와 `data/prescriptions.json`은 아직 이 파일을 연동하기 전 **예시 문구
자리표시자**입니다. 담당 D(장예현)가 이 CSV를 체력요인별로 재매핑하는 로직을 이어서
작업하면 됩니다.

1. **영상·센터 데이터는 아직 목업입니다.** 서비스키 발급 후 위 "실제 API로 전환"

3. **청소년/유소년 근력 측정 방식은 단순화했습니다.** 기획안 4-5절은 연령군별로 항목

   분기합니다. 10대 이하 전용 항목 반영은 2단계 작업입니다.
4. **3개월 재점검은 시뮬레이션입니다.** 실제 3개월을 기다릴 수 없어, 재측정값을 직접
   입력(또는 완료 루틴 수 기반 자동 추정)해 비교합니다(기획안 14절 9번 항목과 동일한 접근).

## 코드 스타일 관련 안내

이 웹 서버/프런트엔드는 Node.js(JavaScript)로 작성했습니다. 저장소의 `AGENTS.md`는
`notebooks/`·`src/`의 Python 3.11 분석 코드를 대상으로 한 규칙(들여쓰기 4칸,
snake_case, 한국어 주석 등)이라, 이 `website/` 폴더는 별도 스택으로 두었습니다.
`fitness_age.py`(참조 구현)의 로직은 `server.js`로 그대로 포팅했으니, `notebooks/`·
`src/`에서 이 로직을 Python으로도 계속 쓰는 데는 지장이 없습니다 - 두 구현이 같은
`data/fitness_distribution.json`(원본은 `fitness_distribution.csv`)을 보고 있으면 됩니다.
`website/.gitignore`에 `node_modules/`, `config.json`, `.env`를 이미 제외해 두었습니다.
